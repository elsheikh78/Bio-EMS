# BIO-EMS Monitor — native Android and iOS customer app

Version 0.1.0 is an Expo/React Native customer monitoring client, not an embedded browser. It uses the existing BIO-EMS project logo and viewer accounts. It is read-only: no company administration, commissioning, configuration changes or alarm acknowledgement.

## Implemented

- Native sign-in; bearer session stored in Android encrypted storage/iOS Keychain through Expo SecureStore. Passwords are not persisted. Server sessions expire after eight hours and are immediately rejected when a viewer is disabled or its password is changed.
- Customer-scoped sites/rooms, all exported enabled sensor readings, recorded times, active and recovered alarms, site filtering, and refresh every 30 seconds while active.
- Arabic/English, RTL/LTR content alignment, persistent language preference, and original project branding.
- Stale readings and unavailable telemetry are never presented as healthy. Active alarms remain visible while disconnected. Last successful data is held only in memory and cleared on sign-out/account change.
- Opt-in vibration and local notification sound when a new active alarm arrives **while the app is open**. Initial/historical alarms do not trigger a new alert. Background polling and native remote push are **not implemented** in this version. The Settings screen states this explicitly.
- Returning to the foreground refreshes data. Requests are cancelled on account change. Native logout revokes only that native session; local sign-out while offline leaves the server session to expire.

## Server prerequisite

Deploy the matching `company-cloud/src/viewer.mjs` change before using this app. No new D1 migration is needed. `/api/mobile/viewer/login` accepts the same customer viewer username/password and returns an opaque expiring bearer session. Only login, overview and logout exist in this namespace. Cookies/company credentials are not accepted for native authentication, and foreign browser origins are rejected. Existing web viewer sessions and Web Push behavior remain separate.

The fixed HTTPS origin is `https://bioems-company.bioems-egypt.workers.dev`. This prevents credentials from being directed to arbitrary addresses. For another deployment, edit `src/api.ts` and rebuild; it is not a customer setting.

## Development and validation

```sh
cd mobile
npm ci
npm run typecheck
npm test
npx expo install --check
npx expo prebuild --no-install --platform all
npm run export
```

`npm run export` creates JavaScript bundles. **It does not produce an APK, AAB or IPA**. Native folders generated by prebuild are ignored and regenerated from `app.config.js`.

For a local Android device/emulator with Android Studio/SDK configured, use `npm run android`. For an iOS device/simulator, use `npm run ios` on macOS with Xcode and CocoaPods. Notification behavior must be tested in a development/standalone build; Expo Go is not the acceptance target.

## Android QA APK without an Expo account

The `Customer mobile Android and iOS` GitHub workflow can generate an arm64 Android QA APK directly using the Android SDK and Gradle, after tests/export pass. It uses a **development certificate**, a separate `com.bioemsegypt.monitor.pilot` application ID and the name BIO-EMS Monitor Pilot. This is for sideloaded testing, not Play Store publication. Do not promise production upgrade compatibility or trust this certificate as a commercial signing identity. Build success and real-device acceptance must be recorded separately.

## Signed Android and iOS builds

The owner must use their own Expo/EAS account and register the app project. Proposed identifiers are `com.bioemsegypt.monitor` for both platforms; verify ownership before first release. Create/link the EAS project using the current EAS CLI (`npx eas-cli@latest init`), preserve the returned project ID using `EXPO_PUBLIC_EAS_PROJECT_ID`, then configure credentials under the owner's account. No project ID or signing credentials are invented or committed.

```sh
cd mobile
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile preview
```

`preview` requests an Android APK for direct installation. Internal iOS distribution requires Apple Developer enrollment, a signing certificate/provisioning profile and registered test-device UDIDs. An IPA cannot be installed on arbitrary iPhones. For TestFlight/store distribution use the production profile and the owner's App Store Connect/Google Play accounts. Google Play publication requires a Play developer account; direct APK testing does not.

For later native background notifications, provision Android FCM v1 and Apple APNs credentials, add authenticated device registration and server delivery/receipts, and complete real-device tests. Existing browser Web Push must not be advertised as native push.

## Release acceptance still required

1. Deploy the mobile API; sign in with two separate customers and verify isolation.
2. Compare room/readings/alarm timestamps to the installed client's latest export.
3. Disconnect/reconnect the phone and source PC; stale state must remain explicit.
4. Trigger a test alarm while the app is active; verify opt-in sound/vibration and deduplication.
5. Disable viewer/change password centrally, sign out, change account, and test session expiry.
6. Build signed APK/IPA and test on physical Android/iPhone, including Arabic keyboard, text sizing, safe areas and app foreground/background transitions.

Code tests and JavaScript exports are not evidence of signed binary installation or store acceptance.
