تحديث 0.6.2 — الاختبارات والتأهيل في الهاردوير تيستر فقط
تم إزالة Hardware Lab من واجهة System Owner؛ السجلات القديمة محفوظة للقراءة.
التبويب 7 Qualification guide يشرح 18 خطوة مراجعة وتأهيل.
اضغط Select staged qualification scope ثم أدخل بيانات التجميع وابدأ الاختبار.
سجل أدلة كل خطوة بالترتيب من Inspection / evidence واربط أرقام اختبارات القراءات الفعلية.
الخطوة السابقة يجب أن تنجح قبل تسجيل PASS للخطوة التالية؛ النواقص تمنع نجاح التأهيل.
دي قائمة تأهيل يدوية وليست قراءة تلقائية لـ16 حساس؛ القراءات التلقائية لها الاختبارات المنفصلة.
التفليش من التبويبين 5 و6 كما هو موضح أدناه؛ تهيئة وتركيب جهاز العميل ما زالت بالمنصة.

تحديث 0.5.0 — تفليش فيرموير التشغيل من داخل Hardware Tester
افتح التبويب 6 Operating firmware بعد إيقاف أي اختبار.
أدخل رقم التجميع واسم المختبر و COM وعنوان النانو من Test setup.
افصل RS485 والتغذية الخارجية، ووصل لوحة واحدة USB فقط.
للنانو المختبر EMS-S-001 اختر Nano bench.2 new bootloader 115200.
اترك D7/D8 مفتوحين للعنوان 1، وافصل D0/D1 عن RS485.
اضغط Detect operating target ثم Flash operating firmware and verify وانتظر SUCCESS.
كرر للـ Main باختيار Main ESP32-S3 pilot.9 ومنفذ COM الخاص به.
بعد نجاح اللوحتين افصل التغذية وأعد التوصيلات، وافصل USB النانو.
غذ التجميع بمصدر تم فحصه، ووصل USB الـMain فقط بمسار تغذية موثوق.
اختر Main + Nano / 4 sensors via RS485 وحدد Main COM والعنوان.
لا يحتاج اختبار الربط تسجيل دخول للمنصة. التفليش لا يجهز هوية العميل أو الربط بالمنصة.
احتفظ بنسخة احتياطية قبل تغيير جهاز سبق تشغيله عند عميل.
التبويب 5 ما زال خاصاً بفيرموير QC للحساسات المنفردة، وليس فيرموير الربط.
اقرأ OPERATING_FIRMWARE_GUIDE.md للخطوات وحدود الاختبار.

برنامج BIO-EMS Hardware Tester المستقل لمراقبة جودة التجميع

فك ضغط الحزمة وافتح BIO-EMS-Hardware-Tester.exe بدون تشغيل المنصة.
للتجربة بدون أجهزة: أدخل رقم وحدة واسمك واضغط DEMO. تقاريره محاكاة فقط.
تحديث 0.3.0: التفليش من داخل البرنامج مباشرة بدون Arduino IDE أو Python عند العميل.
فك الحزمة بالكامل واحتفظ بمجلدي firmware وruntime بجانب ملف EXE.
أدخل رقم الوحدة واسم المختبر واختر COM من Test setup.
افتح تبويب 5 Flash QC firmware واختر ESP32-S3 أو Nano والـbootloader المناسب 57600 أو 115200.
اضغط Detect selected board ثم Flash QC firmware and verify.
أكد اختيار البوردة وتوصيل USB فقط وفصل المكونات المتعارضة. التفليش يستبدل فيرموير التشغيل.
انتظر اكتمال التحقق وظهور SUCCESS قبل بدء Start hardware run. لا تفصل USB أثناء التفليش.
النجاح يشمل تحقق أداة التفليش وظهور stream مطابق لفيرموير الاختبار، ولا يعني نجاح الحساسات.
سجلات التفليش محفوظة في firmware-events؛ سجل التفليش الناجح يرفق بالاختبار المطابق في نفس الجلسة.
بعد الاختبارات أعد الفيرموير التشغيلي بالطريقة المعتمدة قبل توصيل النظام المتكامل.
قد يحتاج Windows تعريف USB الخاص بالبوردة. الكود النصي القديم غير متوافق.
ESP32: حساس واحد على GPIO4 و3V3 وGND ومقاومة 4.7k بين البيانات و3V3.
افصل SD وباقي المكونات لتعارض GPIO4، وافصل الكهرباء قبل تغيير الأسلاك.
Nano: أربعة حساسات مستقلة على D2-D5 بمقاومة لكل خط إلى 5V. افصل HW-519 من D0/D1.
راجع وظائف أسلاك الحساس مع المورد، ولا تعتمد على اللون وحده.

1- أدخل رقم الوحدة واسم المختبر ورقم ومراجعة الإجراء واختر نطاق الاختبار.
2- راجع حدود القبول قبل البدء؛ الحدود الافتراضية أمثلة تحتاج اعتمادك.
3- اختر COM ثم Start hardware run. القراءات والرسم في Live sensors.
4- سجل أدلة الفحوص من Inspection. نجاح الجهد يتطلب القيمة وحدود القبول وهوية الأفوميتر.
5- استخدم الإنجليزية في حقول التقرير لضمان طباعة سليمة.
6- اضغط STOP AND FINALIZE RUN ثم اختر السجل من Records.
7- Analyze لتحليل النتيجة، وExport PDF + JSON + CSV لحفظ التقرير والقراءات.
8- التقرير قابل للطباعة وفيه بيانات الوحدة وخانة توقيع ومراجعة مسؤول الجودة.
9- الناقص INCOMPLETE والفاشل FAIL والناجح PASS في النطاق المختار فقط.
10- لا تمسح المحاولات الفاشلة. ابدأ محاولة جديدة واربطها برقم السابقة في الإجراء.

اختبارات RS485 والشبكة وSD وGSM والبطارية بهذه النسخة تسجيل أدلة يدوية.
القراءات المباشرة للحساسات وتحليلها آليان. نجاح حساس واحد لا يعتمد الجهاز كله.
راجع README للتوصيل وحدود البرنامج وحفظ السجلات واستعادة فيرموير التشغيل.


تحديث 0.2.0 / pilot.9:
للتجميعة الحالية اختر Main + 1 SIM / Rev B. فحص RTC مطلوب في هذا النطاق، وبطارية UPS غير المركبة خارج نطاقه.
ابدأ سجل HARDWARE يدوي ثم اختر COM الخاص بالـMain واضغط Capture Main pilot.9 USB diagnostics.
يلزم الفيرموير التشغيلي pilot.9 ومسار تغذية USB آمن. البرنامج يجمع status وstorage وrtc وsimscan وgsmdiag ويحفظ النص في سجل التقرير.
زر التقاط التشخيصات لا يغير الساعة ولا يرسل SMS ولا يعمل commissioning أو flashing؛ التفليش له تبويب مستقل. يجب مراجعة رقم الفيرموير الظاهر في الناتج.
تسجيل تشخيصات USB لا يعطي PASS تلقائيًا؛ يلزم فحص القياسات الفعلية واسترجاع الساعة بعد فصل الكهرباء واستلام رسالة الاختبار يدويًا.
الـQC sketch للحساسات المنفردة مختلف عن الفيرموير التشغيلي. افصل SD عند اختبار الحساس على GPIO4 وأعد الفيرموير التشغيلي بعد الاختبار.

تحديث 0.4.0: اختبار Main ثم RS485 ثم Nano والأربع حساسات من البرنامج.
اختر Main + Nano / 4 sensors via RS485 ورقم SIM ثم COM الخاص بالـMain.
يلزم فيرموير التشغيل pilot.9 للـMain وbench.2 للنانو، وليس QC. تحميل فيرموير التشغيل متاح الآن من التبويب 6 Operating firmware داخل التيستر.
افصل USB النانو أثناء RS485 وراجع تغذية التجميعة ومسار USB قبل التشغيل.
اضغط Start hardware run لعرض القراءات والرسم وحفظها وتحليلها وتصدير التقرير.
سجل فحص الأسلاك والجهد واستجابة كل حساس والاستعادة في Inspection؛ النواقص تمنع PASS.
البرنامج يرصد Main ورقم SIM والمدخل؛ رقم ROM وعمر عينة النانو غير متاحين في هذا المسار.
