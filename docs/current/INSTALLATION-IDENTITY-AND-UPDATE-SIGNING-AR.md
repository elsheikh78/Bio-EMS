# هوية تثبيت العميل وتوقيع التحديثات — دليل التشغيل

تاريخ المراجعة: 11 أكتوبر 2026. مرجع التنفيذ: PR [#290](https://github.com/elsheikh78/Bio-EMS/pull/290)، مدمج في `main@70108f05bfc0f1826edf44db1eb15bc291e0ea33`. إصدار المنتج ما زال `0.20.0`؛ هذه إضافة للبيلوت وليست إعلان إصدار تجاري جديد.

## 1. البيانات التي تحدد العميل والتثبيت

| البيان | وظيفته | المصدر |
| --- | --- | --- |
| Customer Name / Code | اسم العميل وكوده | بيانات Windows Setup وسجل العميل المطابق |
| Site Name / Code | اسم الموقع وكوده | بيانات Windows Setup والموقع المرتبط بالعميل |
| Installation ID | UUID لتثبيت Windows على الجهاز المضيف | إيصال تهيئة هوية التثبيت |
| Customer / Site numeric ID | مرجع محلي لسجل قاعدة البيانات | سجل المنصة؛ لا يُعامل كهوية عالمية |
| معرّف دورة حياة التهيئة | UUID لسجل إعداد المناطق والأجهزة والقنوات | سجل دورة الحياة؛ مستقل عن UUID الجهاز المضيف |

استخدم **Installation ID الخاص بالجهاز المضيف** عند تنظيم سجلات التثبيت. لا تنسخ رقم دورة حياة التهيئة على أنه هوية Windows. إذا كان لدى العميل تثبيتان مستقلان، احفظ سجلًا لكل تثبيت تحت ملف العميل نفسه.

هذه البيانات تُقرأ من Setup وتُطابق مع سجلات العميل والموقع؛ أزرار النسخ والتصدير لا تنشئ هوية جديدة ولا تغير الهوية الموجودة. عند تعذر المطابقة، عالج بيانات التهيئة أولًا بدل اختراع كود بديل.

## 2. خطوات تسجيل العميل لدى الشركة

1. افتح منصة العميل باستخدام حساب **System Owner** ومسار الدخول المعتمد له.
2. افتح **تهيئة التركيب**: `/system-owner/installations`.
3. في قسم **هوية العميل والموقع المثبتة** راجع اسم وكود العميل، اسم وكود الموقع، و**معرّف تثبيت الجهاز المضيف**.
4. اضغط **تصدير بيانات التثبيت**. يحفظ المتصفح ملف JSON بالاسم `BIO-EMS-Installation-<Installation ID>.json`.
5. احفظ الملف في مجلد العميل لدى الشركة. سجل إصدار البرنامج المثبت وتاريخ التسليم في سجل الشركة؛ ملف التصدير الحالي لا يحتوي عليهما.
6. استخدم **نسخ بيانات التثبيت** لوضع نفس بيانات السجل بصيغة JSON في سجل إلكتروني. إذا رفض المتصفح الحافظة، استخدم التصدير.
7. كرر العملية لكل تثبيت مستقل. عند تحديث المنصة، تحقق أن هوية التثبيت ظلت كما هي.

الأزرار متاحة قبل إنشاء مسودة التهيئة، ولا تحفظ مسودة ولا تعدل المناطق أو الأجهزة. وجودها يتطلب واجهة مبنية من PR #290 أو أحدث؛ لا يظهر التعديل داخل Setup أقدم بمجرد تحديث ملفات Git المحلية.

## 3. محتويات ملف التصدير

الملف يحتوي فقط على:

- `schemaVersion`، `product`، `exportedAt` بصيغة UTC.
- `installationId`، و`source=INSTALLER_PROVISIONING_RECEIPT`.
- `customer`: الرقم المحلي والكود والاسم.
- `site`: الرقم المحلي والكود والاسم.

لا يتضمن إيصال التهيئة الخام أو مفاتيح خاصة أو كلمات مرور أو أكواد الربط. الملف سجل معلومات غير موقّع؛ لا يُستخدم كنسخة احتياطية أو شهادة تشغيل أو تصريح بالتحديث، ولا يكفي وحده لتنفيذ نقل الهوية أو الترخيص.

## 4. قراءة الهوية عند التشخيص

في التثبيت القياسي، مصدر البيانات هو:

```text
C:\ProgramData\BIO-EMS\licensing\installation-provisioning-receipt.json
```

المسار الفعلي الذي تقرؤه خدمة الهوية تحدده إعدادات `BIOEMS_INSTALLATION_PROVISIONING_RECEIPT_PATH`. استخدم واجهة التصدير للسجل المعتاد. عند الحاجة للتشخيص على المسار القياسي، يعرض هذا الأمر البيانات المحددة فقط:

```powershell
$r = Get-Content 'C:\ProgramData\BIO-EMS\licensing\installation-provisioning-receipt.json' -Raw | ConvertFrom-Json
[PSCustomObject]@{
    InstallationID = $r.installationId
    CustomerName   = $r.customerSite.customerName
    CustomerCode   = $r.customerSite.customerCode
    SiteName       = $r.customerSite.siteName
    SiteCode       = $r.customerSite.siteCode
} | Format-List
```

## 5. كيف يعمل توقيع التحديث الحالي؟

| العنصر | مكانه / وظيفته |
| --- | --- |
| مفتاح توقيع التحديث الخاص | لدى جهة بناء وتوقيع إصدار الشركة؛ لا يوضع في Setup العميل |
| شهادة التوقيع العامة | لدى العميل للتحقق من ملف الشركة؛ تحتوي المفتاح العام وليست مفتاحًا خاصًا للعميل |
| ملف التحديث | ملف **BIO-EMS Client Setup EXE** موقّع بتوقيع Windows Authenticode |
| هوية العميل والتثبيت | بيانات مستقلة عن مفاتيح التوقيع؛ التحديث الحالي يحافظ على UUID الأصلي |

صفحة ADMIN `/system-update` تقبل ملف EXE المعتمد وتتحقق من توقيع Windows ومن ناشر BIO-EMS الموثوق وبيانات المنتج والإصدار وsource commit. يظهر الملف للمراجعة قبل تنفيذ التثبيت. ملف ZIP أو Firmware أو Setup المصنع ليس مدخلًا صالحًا لهذه الصفحة.

**الوضع المنفذ:** تحديث عام واحد للمواقع المتوافقة. لا يوجد حاليًا شرط داخل حزمة التحديث يقيدها بعميل أو `Installation ID` معين. تصدير الهوية لا يضيف هذا الشرط.

**قيد البيلوت الحالي:** CI يولد شهادة توقيع ذاتية جديدة لكل Build. لقبول EXE من Build مختلف، يحتاج مسؤول Windows تجهيز شهادة ذلك البناء المعتمدة من الشركة بالطريقة الموثقة. صفحة التحديث لا تثق تلقائيًا في شهادة يحملها الملف المرفوع. اعتماد مفتاح/شهادة مستقرة للشركة ودورة تدوير محكومة خطوة مستقلة قبل التشغيل التجاري.

التصميم التجاري المستهدف يمكن أن يستخدم مفتاح توقيع واحدًا للشركة لكل العملاء؛ تخصيص التحديث لعميل يحتاج بيانات هدف موقّعة والتحقق منها في المنصة، وليس مفتاح توقيع مختلفًا لكل عميل. هذا التخصيص **غير منفذ** في PR #290. مفاتيح الترخيص وربط الأجهزة مستقلة عن توقيع تحديثات Windows.

التحديث عبر الإنترنت معطل افتراضيًا؛ التحقق نفسه ينطبق على الملف المحلي وعلى التنزيل المستقبلي. `SHA256SUMS` للتحقق من البصمات ولا يحل وحده محل توقيع ناشر موثوق.
