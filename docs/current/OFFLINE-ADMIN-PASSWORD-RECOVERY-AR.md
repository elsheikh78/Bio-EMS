# استعادة كلمة مرور Admin بملف موقّع من الشركة

هذه وظيفة استعادة محلية دون خادم cloud. تتطلب Client Setup وManufacturer Tools مبنيين من التعديل نفسه أو إصدار متوافق، وهوية تثبيت سليمة، ومفتاح استعادة عام معتمد على جهاز العميل. إصدار المنتج يبقى `0.20.0`.

## التجهيز مرة واحدة لدى الشركة

1. ثبّت Manufacturer Tools على جهاز الشركة، وافتح **BIO-EMS Customer ADMIN Recovery**.
2. أدخل Key ID مستقلًا، مثل `admin-recovery-2026`، وعبارة مرور قوية من 16 حرفًا على الأقل.
3. اضغط **Generate encrypted recovery key**، واختر مسار ملف PEM جديد ثم مكان ملف الثقة العام JSON.
4. احفظ ملف PEM المشفّر وعبارة مروره ونسخته الاحتياطية لدى الشركة. لا يُرسل المفتاح الخاص أو عبارة مروره للعميل. الأداة لا تحتوي مفتاح شركة جاهزًا داخل Setup.
5. ملف الثقة العام فقط يجهّز على جهاز العميل بواسطة مسؤول Windows من المصدر المعتمد للشركة:

```powershell
& 'C:\Program Files\BIO-EMS\installer\Install-AdminRecoveryTrust.ps1' -TrustFile 'C:\CompanyFiles\manufacturer-admin-recovery-trust.json'
```

نفذ الأمر في PowerShell بصلاحيات Administrator. المسار `C:\CompanyFiles` مثال لمكان الملف العام الذي أرسلته الشركة. الأداة تتحقق من مفاتيح Ed25519 ثم تحفظ الملف في مجلد licensing المحمي. لا تضف مفتاحًا من ملف مجهول أو من الطلب الذي أرسله العميل. يمكن استخدام المفتاح العام نفسه لكل العملاء مع بقاء التصاريح مقيدة بهوية التثبيت والحساب.

ملف الثقة الفعلي: `C:\ProgramData\BIO-EMS\licensing\manufacturer-admin-recovery-trust.json`. لا يُنشأ تلقائيًا من تصريح مرفوع. إذا لم يُجهّز، تُرفض التصاريح بأمان، ويظل مسار إعادة التعيين المباشر بواسطة System Owner متاحًا.

## الطلب من جهاز العميل

1. من شاشة الدخول اضغط **نسيت كلمة المرور؟** ثم **أنا Admin لدى العميل**.
2. اكتب اسم مستخدم Admin في قسم الاستعادة بالملف، ثم اضغط **تصدير طلب الاستعادة**.
3. أرسل JSON إلى الشركة بالطريقة المتفق عليها. صلاحية الطلب 24 ساعة. لا تنشئ طلبًا جديدًا بلا حاجة؛ احفظ الطلب الذي أرسلته.
4. الطلب يحتوي UUID للتثبيت والطلب، بيانات اسم/كود العميل والموقع، اسم الحساب، وتحديًا عشوائيًا. لا يحتوي كلمة المرور. شكله لا يؤكد وجود الحساب أو نوعه.

## التصريح من Manufacturer Tools

1. اختر ملف الطلب عبر زر الاستعراض؛ راجع العميل والموقع والحساب وInstallation ID ووقت انتهاء الطلب.
2. تحقق من هوية طالب الاستعادة عبر وسيلة الاتصال المعروفة لديك. ملف الطلب نفسه غير موقّع؛ لا تعتبر الأسماء المكتوبة فيه دليل ملكية.
3. اختر **مفتاح الاستعادة المشفّر المستقل**، وأدخل Key ID المطابق للمفتاح العام المثبت وعبارة مرور المفتاح.
4. حدد صلاحية التصريح من 1 إلى 60 دقيقة؛ الافتراضي 60 دقيقة، ولا تتجاوز نهاية صلاحية الطلب.
5. علّم تأكيد التحقق من العميل واضغط **Issue signed reset permit**. راجع رسالة التأكيد ثم اختر ملف JSON جديدًا.
6. أرسل التصريح فقط للعميل الذي تحققت منه. الشركة لا تدخل كلمة مرور جديدة ولا تعرفها؛ الملف الموقّع تصريح تعيين وليس كلمة مرور.

## تعيين كلمة المرور عند العميل

1. من قسم الاستعادة اختر **اختيار تصريح الشركة** ثم **التحقق من التصريح**.
2. المنصة تتحقق من التوقيع والغرض والمفتاح المعتمد ومن UUID التثبيت والطلب والحساب والتحدي والصلاحية والحالة الحالية للحساب.
3. عند النجاح تظهر حقول **كلمة المرور الجديدة** و**تأكيد كلمة المرور** فقط. تصريح هذه الصفحة لا يمنح جلسة Admin ولا يسمح بتعديل بيانات المنصة.
4. اختر كلمة لا تقل عن 12 حرفًا وبها حرف إنجليزي كبير وصغير ورقم. مدة الإذن المقيد 10 دقائق كحد أقصى، أو ما تبقى من التصريح إن كان أقل.
5. اضغط **حفظ كلمة المرور الجديدة**. يُستهلك الطلب والتصريح داخل معاملة واحدة، ثم ارجع لشاشة الدخول وادخل بالطريقة المعتادة.
6. إذا انتهى الإذن قبل الحفظ، أعد التحقق من التصريح ما دام التصريح والطلب صالحين ولم يُستهلكا؛ الإذن الجديد يلغي الإذن السابق لنفس الطلب. إذا انتهى التصريح، تطلب من الشركة تصريحًا جديدًا لطلب صالح، أو تصدر طلبًا جديدًا.

## ضوابط التنفيذ وحدوده

- توقيع Ed25519 بغرض `CUSTOMER_ADMIN_PASSWORD_RESET` مستقل عن Authenticode الخاص بملفات Update وعن System Owner commissioning.
- الطلبات والحالة وبصمة التحدي والإذن مخزنة في SQLite؛ الإذن نفسه يبقى في ذاكرة صفحة المتصفح ولا يخزن في localStorage أو sessionStorage. إعادة تحميل الصفحة تتطلب التحقق مجددًا.
- تُرفض الحسابات غير الموجودة وغير النشطة وغير ADMIN عند التحقق؛ الرد عام. تغير كلمة مرور الحساب بطريق آخر يبطل الطلب القديم.
- منع الاستخدام الثاني يعتمد على الحالة المخزنة في قاعدة البيانات الحالية. استعادة Backup أقدم قد تعيد حالة طلب قديم؛ لا تُستخدم نسخ قديمة كوسيلة استعادة كلمة المرور. صلاحيات الطلب والتصريح قصيرة ومقيدة بوقت الجهاز.
- إلغاء المفتاح في ملف الثقة يمنع التصاريح والأذونات التي صدرت منه. تغيير ملف الثقة يتم بواسطة مسؤول Windows، وليس عبر واجهة الدخول.
- ينطبق rate limit على الطلب والتحقق والحفظ. يُسجل إنشاء الطلب واعتماد التصريح وإتمام تغيير كلمة المرور في سجل الاستعادة دون كلمات مرور أو إذن خام.
- الاستعادة لا تصدر JWT ولا جلسة تشغيل. هذا التعديل لا يغير سياسة صلاحية جلسات تسجيل الدخول السابقة؛ إعادة تعيين كلمة المرور المباشرة لها نفس السياسة الحالية.
- لا توجد رسالة بريد أو WhatsApp تلقائية. تبادل الملفات يتم عبر الشركة والعميل. تصريح الاستعادة حساس؛ أرسله لصاحب الطلب المعتمد.
- تثبيت الأداتين لا يكمل تجهيز المفتاح العام وحده. يلزم تنفيذ خطوات تجهيز المفتاح أعلاه مرة واحدة قبل استخدام المسار ميدانيًا.

## الاختبارات

اختبارات backend تغطي التوقيع والتطابق والصلاحية والمفتاح الملغى، رفض التلاعب والغرض المختلف والحساب غير المؤهل، الاستهلاك مرة واحدة، وكلمة المرور الجديدة. اختبارات الواجهة تغطي تصدير الطلب والتحقق قبل عرض كلمة المرور وعدم إصدار تسجيل دخول. Windows CI ينفذ اختبارًا على المنصة المثبتة بأداة توقيع مبنية من الكود، ثم يرفض التلاعب وإعادة الاستخدام ويتحقق من دخول Admin بالكلمة الجديدة. نجاح CI لا يُعد قبولًا ميدانيًا لجهاز العميل.
