# SD offline telemetry replay — controller pilot.6

Source implementation added 18 October 2026. Physical card, power-loss and UPS qualification remain mandatory.

The ESP32-S3 Main collects up to four SIM-D4 modules. A timestamped sample that fails HTTPS delivery is stored on its FAT SD card. A checksum-protected record includes its original binding and acquisition timestamp; credentials are never written to the card. After connection returns, at most eight records are replayed per polling cycle as `REPLAY`. A record is removed only after HTTP 202 and successful local acknowledgement. Corrupt records, failed deletions or different installation bindings stop replay rather than silently discard history. Current live samples are attempted before replay.

The backend accepts optional `timestamp` and `mode` fields on authenticated device telemetry. Replay requires the acquisition timestamp; timestamps more than one minute ahead of server time are rejected. Legacy requests without these fields retain server timestamping. The processing pipeline now reports whether all channels were accepted, preventing a false HTTP 202 for rejected device/channel data. Influx writes retain original timestamps; retries of the same device/sensor/time target the same point. Replayed samples do not evaluate live alarms. A lost acknowledgement can cause a repeated history write; this is at-least-once delivery, not a transaction across FAT and InfluxDB.

After each cold boot, a previously stored provisioning epoch is used only for TLS bootstrap. Accurate historical buffering requires a fresh USB `settime` or time from a successful authenticated HTTPS response (`x-bioems-utc-epoch`). This uses the local platform and does not require internet/NTP. Before time is trusted, live readings use server timestamps and a disconnected device logs `TIME_UNTRUSTED` instead of inventing historical time. The central battery maintains running-clock continuity during a normal external power outage. Hardware RTC support is not part of this implementation.

Default queue limit: 20,000 four-channel samples (configurable 1–20,000 to bound FAT directory entries). For four fitted modules and an ideal five-second acquisition period, this is approximately 6.9 hours of backlog; actual timing includes network/RS485/SD latency and this is not a guaranteed retention interval. Queue limits and card capacity are different. A full queue preserves old records, rejects additional writes and logs an explicit error. A failed append can leave a torn record that blocks subsequent replay for manual recovery. FAT is not a power-loss-proof database; battery qualification and card endurance testing are essential. No automatic formatting or automatic deletion of damaged/history records is performed.

`storage` USB diagnostic reports mount, trusted-time state and pending record count. SD failures also emit explicit serial logs (`STORAGE_UNAVAILABLE`, `STORAGE_WRITE_FAILED_OR_FULL`, `STORAGE_CORRUPT`, `STORAGE_ACK_FAILED`). This change does not add a customer UI for SD/battery health, remote card recovery or card hot-swap. Insert the card before boot and power down before removal. Failed mounts require repair and reboot. Removing or manually changing queue files while running is unsupported.

Build the backend/client package and controller firmware together. Controller identity is `0.1.0-pilot.6`; installer manifest gates were moved with it. Nano SIM-D4 firmware remains unchanged. Existing provisioned boards need the new governed firmware; a software-only Windows update does not install code on an ESP32 by itself.

See [central battery and SD wiring](../hardware/MAIN-CENTRAL-BATTERY-AND-SD-2026-10-18.md) for the one-battery/four-SIM topology and physical acceptance steps.

The ESP-IDF single-factory large application partition (1500 KiB) is selected to fit the added FAT/SD code. NVS/PHY and the application start offset remain at the standard locations. Use the governed full flash package including its partition table; a bare application binary is not a complete upgrade from the old 1 MiB layout. This does not add ESP32 OTA partitions.
