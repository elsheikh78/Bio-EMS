# حالة SEC-OWNER-01 وخطوات الوصول إلى الدمج

آخر Commit برمجي متحقق منه: `cf66ebe354986c1db03df3d4da57bfb9e1979cda`

## 1. ما تم تنفيذه

- فصل `SYSTEM_OWNER` بالكامل عن مستخدمي العميل وSetup وواجهات وصلاحيات `ADMIN`.
- إنشاء طلب Commissioning مرتبط بهوية التثبيت ولا يحتوي مفتاح الشركة الخاص.
- أداة Offline لتوقيع حزمة Ed25519 قصيرة العمر ومستخدمة مرة واحدة.
- ربط الحزمة بالتثبيت والعميل والموقع، ورفض العبث والانتهاء والتكرار والجهاز المختلف.
- إنشاء `SYSTEM_OWNER` منفردًا فقط بعد التحقق من التوقيع.
- إلغاء مسار Bootstrap المحلي القديم الذي كان يتجاوز حماية الشركة.
- MFA/TOTP إلزامي قبل منح جلسة Owner كاملة.
- قفل الحساب بعد 5 محاولات فاشلة لمدة 15 دقيقة.
- Rate Limit مستقل: 10 طلبات دخول لكل عنوان IP خلال دقيقة مع `429` و`Retry-After`.
- جلسات محفوظة ومنتهية الصلاحية وقابلة للإلغاء منفردة أو بالكامل.
- صلاحيات دعم مؤقتة محددة النطاق والمدة وقابلة للإلغاء فورًا.
- سجل تدقيق أمني مع منع تسجيل كلمات المرور وTOTP والـTokens والأسرار.
- منع `ADMIN` من تعداد أو إنشاء أو تعديل أو حذف أو انتحال Owner.
- Trust Keyring ثابت ومحمي، مع رفض المفتاح المجهول أو الملغي أو غير Ed25519.
- عقد بناء يفشل مغلقًا: Pilot يمنع Production keyring، وProduction يرفض البناء بدونه.
- توثيق حفظ المفتاح والتدوير والإلغاء والتعافي واستبدال جهاز العميل.

## 3. لماذا لم يتم الدمج بعد

الكود البرمجي مكتمل، لكن قبول Production يحتاج مفتاح الشركة الحقيقي ودورة تشغيل كاملة
به. الدمج قبل ذلك قد يجعل `main` يبدو Production-secure دون إثبات أن المفتاح الحقيقي
والـKeyring والتوقيع Offline يعملون معًا.
